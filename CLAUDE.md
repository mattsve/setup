# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Purpose

Ansible configuration for provisioning and managing home lab servers (Proxmox host and its LXC containers), plus an OpenTofu configuration (`tofu/`) for provisioning the Proxmox guests themselves. OpenTofu owns resource lifecycle (creating/destroying LXCs/VMs); Ansible owns in-guest configuration on top of whatever OpenTofu creates — the two don't overlap.

## Setup

```bash
ansible-galaxy collection install -r ansible/requirements.yaml
```

Requires the 1Password CLI (`op`) signed in — secrets are fetched via `community.general.onepassword` lookups in `group_vars`, not stored in the repo. `ansible/.env` (gitignored) holds `PROXMOX_TOKEN_SECRET`, used via `op run --env-file .env -- ...`.

## Commands

All commands run from the `ansible/` directory.

List discovered hosts/groups from the dynamic Proxmox inventory:
```bash
op run --env-file .env -- ansible-inventory -i inventory --list
```

Update packages on every LXC container or QEMU VM tagged `managed-updates` in Proxmox:
```bash
op run --env-file .env -- ansible-playbook playbooks/update_all_packages.yaml
```

Run a role-tagged playbook (tags: `timezone`, `nut`, `postfix`, `certbot`, `mosquitto`, `autologin`, `plex`, `unused_services`, `update_all_packages`) — like other playbooks, this needs the Proxmox API to discover `pve1` via the dynamic inventory, even though NUT itself connects over plain SSH:
```bash
op run --env-file .env -- ansible-playbook --tags nut playbooks/nut.yaml
```

Apply everything in one go — `playbooks/site.yaml` just `import_playbook`s every other playbook in order, purely as a convenience entrypoint; each playbook remains independently runnable as shown above:
```bash
op run --env-file .env -- ansible-playbook playbooks/site.yaml
```

## Architecture

**One dynamic inventory covers everything:** `inventory/proxmox.yaml` (`community.proxmox.proxmox` plugin) discovers all LXC containers, QEMU VMs, and the node itself on the Proxmox host at `pve1.hem.ingenstans.se` via its API — no `filters`/`exclude_nodes` needed. The plugin auto-creates groups per type (`proxmox_all_lxc`, `proxmox_all_qemu`, `proxmox_nodes`, etc.), and every guest (LXC or QEMU) is additionally grouped by its Proxmox tags (`proxmox_tags_<tag>`, hyphens in tag names become underscores — e.g. tag `managed-updates` → group `proxmox_tags_managed_updates`, wrapped by `managed_updates` in `groups.yaml` — see below). Results are cached (`.cache/`, jsonfile, 1h TTL) since inventory is regenerated from the API on every run. This means every playbook run needs `op run --env-file .env --` (for `PROXMOX_TOKEN_SECRET`), even for playbooks like `nut.yaml` that only ever connect over SSH — the API is just how the host gets discovered.

**Connection vars are scoped by group, not set unconditionally.** LXC containers connect via `community.proxmox.proxmox_pct_remote` (`pct exec`, no SSH) via `inventory/group_vars/proxmox_all_lxc.yaml`; Proxmox nodes connect over SSH as root via `inventory/group_vars/proxmox_nodes.yaml` (`ansible_host` derives from `inventory_hostname`, so it generalizes to future nodes). These live in `group_vars` rather than the dynamic inventory's `compose`, which has no clean way to set a var conditionally per host type.

**Playbooks target a group instead of a boolean flag.** `inventory/groups.yaml` is a small static inventory source that exists purely to define these groups (merging into hosts discovered by the dynamic Proxmox inventory, not adding new ones):
- `postfix_relay: children: [proxmox_nodes]` — postfix relay currently applies to every Proxmox node, expressed as a child-group relationship so newly discovered nodes are included automatically, not a list that needs manual upkeep.
- `nut: hosts: [pve1]` — NUT is tied to which physical host has the USB UPS attached, which doesn't follow from any group, so it's an explicit host list.
- `managed_updates: children: [proxmox_tags_managed_updates]` — a clean alias for whichever LXC containers/QEMU VMs happen to be tagged `managed-updates` in Proxmox right now. `proxmox_tags_managed_updates` is auto-generated by the dynamic inventory's `keyed_groups` (named after the raw tag); wrapping it means the playbook targets a name defined here rather than a plugin implementation detail, and opting a guest in/out is just a Proxmox tag edit.
- `certbot: children: [proxmox_tags_certbot]` — same alias pattern as `managed_updates`: whichever guests are tagged `certbot` in Proxmox get Let's Encrypt certs.
- `mosquitto: children: [proxmox_tags_mosquitto]` — same alias pattern as `managed_updates`/`certbot`/`autologin`: deploying it is an opt-in choice (tag the guest `mosquitto` in Proxmox), not something fixed by physical hardware the way `nut` is, so new single-purpose apps like this should follow the tag pattern rather than an explicit host list — it needs no `groups.yaml` edit per new host, just a Proxmox tag.
- `autologin: children: [proxmox_tags_autologin]` — same alias pattern as `managed_updates`/`certbot`: whichever LXC containers or QEMU VMs are tagged `autologin` in Proxmox get root auto-logged-in on their console.
- `unused_services: children: [proxmox_all_lxc]` — unconditional, like `postfix_relay`: applies to every discovered LXC container, not an opt-in tag, since the stock Debian LXC template ships cron and postfix enabled by default and neither is used by this stack.
- `ssh: children: [proxmox_tags_ssh]` — same alias pattern as `certbot`/`mosquitto`/`autologin`, but as an escape hatch rather than an activation switch: `unused_services` disables sshd on every LXC container by default (Ansible reaches them via `pct exec`, not SSH), and tagging a guest `ssh` keeps it running for guests that genuinely need direct SSH access.
- `plex_media: children: [proxmox_tags_plex]` — same alias pattern as `certbot`/`mosquitto`/`autologin`: whichever LXC container or QEMU VM is tagged `plex` in Proxmox gets Plex Media Server installed. Named `plex_media` rather than `plex` specifically to avoid colliding with the `plex` VM's own hostname — Ansible's hosts and groups share one namespace, and a group named the same as a host triggers `Found both group and host with same name` and ambiguous pattern matching.

Each playbook then just does `hosts: <group-name>` with no `when:` gate (e.g. `postfix_relay.yaml` → `hosts: postfix_relay`, `nut.yaml` → `hosts: nut`, `update_all_packages.yaml` → `hosts: managed_updates`) — group membership *is* the switch, so there's one source of truth instead of a group plus a flag that could disagree. `timezone.yaml` is the one deliberate exception: it targets `hosts: all` directly rather than a named group in `groups.yaml`, since every host discovered by the dynamic inventory — guest or node, present or future — should be on the same clock with no opt-in step required.

**Secrets live in `group_vars`, not `defaults`.** Role `defaults/main.yaml` files set non-secret defaults and reference secret variables with `| default(...)` fallbacks; actual secret values are supplied in the relevant role's `inventory/group_vars/<role>.yaml` via 1Password lookups (`op://private/...`). When adding a new secret-consuming role, follow this pattern (define its group in `groups.yaml`, put its secrets in `group_vars/<role>.yaml`) rather than hardcoding credentials or gating with a boolean var. `plex`'s Samba credentials (username hardcoded to `plex`, password via `op://private/l-space/plex`) follow this exact pattern in `group_vars/plex_media.yaml` - named after the `plex_media` group (not `plex`), since `group_vars/<name>` only loads for a group named `<name>` and the group is deliberately not called `plex` (see below).

**Roles** (`ansible/roles/`):
- `timezone` — sets the system timezone to `Europe/Stockholm` (`timezone_name`) via `community.general.timezone`; applied to every host via `hosts: all` (see above), not a `groups.yaml` group.
- `nut` — configures Network UPS Tools (`nut-server` + `nut-monitor`) for UPS monitoring/shutdown; installs a udev rule for the USB UPS.
- `postfix_relay` — configures Postfix to relay outbound mail through an external SMTP host (`smtp.mailbox.org` by default) using SASL auth.
- `certbot` — installs certbot + the Cloudflare DNS plugin, requests a Let's Encrypt cert per host (`certbot_domains` defaults to `<inventory_hostname>.hem.ingenstans.se`, overridable/extendable per host) via DNS-01 (no port 80/443 exposure needed), then enables certbot's own `certbot.timer` for renewal rather than an Ansible-managed cron job.
- `mosquitto` — installs the Mosquitto MQTT broker with persistence enabled and two listeners, both `allow_anonymous: true` (no client auth): a TLS listener (`mosquitto_tls_port`, default 8883) and a plaintext listener (`mosquitto_plain_port`, default 1883) kept alongside it for units that don't support TLS. Consumes the cert the `certbot` role already requested for this host, but copies it into `/etc/mosquitto/certs` rather than pointing the listener at `/etc/letsencrypt/live/...` directly, since that live path is a symlink into `/etc/letsencrypt/archive`, which is `0700 root` and not traversable by the unprivileged `mosquitto` user. The role also drops its own script into certbot's `/etc/letsencrypt/renewal-hooks/deploy/` so the copy gets refreshed (and mosquitto restarted) after every renewal — `certbot` doesn't need to know mosquitto exists; any future cert consumer plugs into that same hook directory rather than the certbot role growing per-consumer logic. `mosquitto_tls_enabled` derives from `'certbot' in group_names` rather than a separate flag, so a host that isn't in the `certbot` group (no cert to serve) automatically falls back to plaintext-only instead of failing on a missing cert file.
- `autologin` — drops a systemd override (`ExecStart=` reset + `agetty --autologin root`) on the guest's tty1 getty unit, restarting it on change so it takes effect without a reboot. Which unit that is depends on guest type (`autologin_getty_unit`, derived from `'proxmox_all_qemu' in group_names` rather than a separate flag, same pattern as `mosquitto_tls_enabled`): LXC containers under systemd use `container-getty@1.service` — what `pct console` attaches to — while QEMU VMs use the plain `getty@tty1.service` a bare-metal host would. Only ever overrides `container-getty@1`/`getty@tty1` (the primary console); other gettys spawned on a guest (e.g. `container-getty@2` for a second configured tty, or `console-getty.service` on LXC's `/dev/console`) are untouched and still prompt for login.
- `unused_services` — disables and stops `cron` and `postfix` on every LXC container (stock Debian template services this stack never uses — mail relaying is `postfix_relay`'s job on `proxmox_nodes`, not here), plus `sshd` unless the guest is tagged `ssh` (`unused_services_keep_ssh`, derived from `'ssh' in group_names` rather than a separate flag, same pattern as `mosquitto_tls_enabled`/`autologin_getty_unit`) — Ansible reaches LXCs via `pct exec`, never SSH, so a listening sshd is unused attack surface by default.
- `plex` — mounts the `//l-space.hem.ingenstans.se/data/media` Samba share read-only at `/mnt/media` (credentials templated into a root-only `/etc/samba/credentials-media` file, referenced from the `_netdev` fstab entry rather than embedded inline), then installs Plex Media Server from its official apt repo (`repo.plex.tv`, signed by the `PlexSign.v2.key` - the original `downloads.plex.tv`/`PlexSign.key` pairing is deprecated and its key carries a SHA1 binding signature that Debian trixie's `sqv` verifier rejects under the post-2026-02-01 crypto policy) via `deb822_repository` (key fetched straight from `plex_apt_key_url` and dearmored by the module itself, no manual `gpg --dearmor` step), and enables/starts the `plexmediaserver` service. No config templating for Plex itself: it's set up and claimed through its own web UI, not a static config file Ansible would own.

`nut`, `postfix_relay`, `mosquitto`, and `autologin` follow the same shape: `defaults/main.yaml` (config vars), `tasks/main.yaml` (install package → template configs, each notifying a handler → enable/start service), `handlers/main.yaml` (restart-on-change), `templates/*.j2` (config files rendered from vars). `certbot`, `unused_services`, `plex`, and `timezone` have no handler or templates: `certbot` because nothing needs restarting on cert issuance/renewal (the standalone timer owns renewal); `unused_services` because it only flips `state`/`enabled` on services that are already installed by the base template, with nothing to render; `plex` because there's no Ansible-managed config file to change, just a package install and a service enable; `timezone` because it's a single module call with no config file or service to restart.

## OpenTofu (`tofu/`)

Provider: `bpg/proxmox`, authenticating with its own `root@pam!opentofu` API token — separate from the `root@pam!ansible` token the Ansible inventory uses, so the two tools don't share credentials (same Proxmox host, `pve1.hem.ingenstans.se`). Run commands from `tofu/`:

```bash
op run --env-file .env -- tofu plan
op run --env-file .env -- tofu apply
```

`tofu/.env` (gitignored) holds `TF_VAR_proxmox_token_secret=op://private/Proxmox/opentofu-api-token` (a field on the same `Proxmox` 1Password item Ansible's secrets live on, alongside `ansible-api-token`). `provider.tf` builds the full `api_token` string (`user!tokenid=secret`) from that var; only the secret half is out of tree.

The `opentofu` token needs more than the `PVEAdmin` role: any resource that downloads by URL (e.g. `proxmox_download_file`, used for CT templates) calls Proxmox's `query-url-metadata` endpoint, which requires `Sys.AccessNetwork` — not covered by `PVEAdmin` or any built-in role short of full `Administrator`. Granted narrowly instead: a custom `AccessNetwork` role (just `Sys.AccessNetwork`) assigned to the token on `/nodes` (propagated, so it covers `pve1` and any future node) rather than handing out `Administrator` on `/`.

State is local (`terraform.tfstate`, gitignored) — deliberate for a single-operator, single-machine homelab: local state avoids standing up a remote backend to solve a locking problem that doesn't exist here. The tradeoff is that state isn't backed up independently of this repo's `tofu/` directory; if this machine is lost with no backup, the Proxmox resources OpenTofu created keep running untouched, but reattaching them requires `tofu import` per resource. `.terraform.lock.hcl` **is** committed (pins provider version/hashes); `.terraform/` and `*.tfstate*` are not.
